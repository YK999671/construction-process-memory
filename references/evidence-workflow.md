# 施工过程证据：批次、辅助资料与查询约束

本文件用于照片与图纸、日报、会议纪要等资料共同分析的场景。SQLite 和原始文件是项目证据的主记录；Obsidian、缩略图页和对话回答是派生视图。下列字段是扩展时的最低信息要求，不表示当前 CLI 已全部支持。

## 一、资料进入项目

- 照片可按 `日期/拍摄批次` 放在本地文件夹；同一天允许多个地点、多个批次，位置未知时不要为命名而猜测。批次来源可为用户文件夹、连续拍摄时间、相似视角；记录采用了哪一种依据。成组只是减少确认次数，不证明每张照片同一楼栋、楼层、轴线或工序。
- 保留原照片及原路径、文件哈希。若要时间或施工内容水印，使用派生副本；记录水印文字及其读取来源，不改写原图。分别保存 EXIF 拍摄时间、文件系统时间、水印时间、人工确认日期，不能仅凭较清楚的一项覆盖其他项。水印写的施工内容是拍摄者提供的线索，需要与画面及其他资料核对。
- 用户可提供独立的日报、会议纪要、图纸、设计变更、验收记录等文件夹。先只读列清文件、文件日期、版本、格式及可解析状态，再读取与本次照片或问题相关的资料。保留原文件路径、哈希、页码/段落或图号、提取文字与原文摘录位置。扫描件、表格和 CAD 不能可靠提取时标记待核，不臆造正文。
- 按照片、文档片段、图纸位置、用户确认分别建立证据条目；同一条工程判断可关联多个条目。关联要写清依据是明确标注、同一部位编号、日期与视角吻合，还是模型候选。资料冲突时保留各原始记录并生成待确认问题。

## 二、集中确认，减少逐张劳动

先对每个批次形成可解释的候选：拍摄时段、项目范围、可能部位、可见施工状态、依据及例外照片。优先请用户确认一条能影响多张照片的共享信息，再处理例外；精确楼层、轴线仅在照片线索足够或查询确实需要时询问。批次确认只传播用户明确确认的字段，例如“都属于售楼处范围”；不得顺带确认每张的楼层、工序或日期。

确认问题宜以缩略图集合呈现，并显示受影响编号、AI 判断、关键依据及不确定点。交互可用三项：“整组这一字段正确”“部分正确，指出例外”“暂时无法确定”，另留自然语言补充。问题按查询价值和影响照片数排序，合并同类冲突，避免对同一事实反复询问。用户回答可以是“P0029–P0031 都属售楼处及附属商铺；P0030 具体位置不确定”。先拆分为项目范围与精确位置，再写现有受支持字段；不可把后半句当作确认。

用户标注的航拍或图纸可作为锚点。基于锚点匹配其他视角仍是模型候选，不能自动升级为人员确认。允许 `unknown`，且不能把未确认照片从后续检索中隐藏。

拍摄阶段可建议每个现场批次先拍一次楼栋/楼层标识，或留下简短语音、文字说明；这是一种可选的减负方式，不作为接收既有照片的前提。GPS 可辅助室外场地位置，不能单独证明室内楼层或轴线。

## 三、五项硬约束

### 1. 统一部位编号，保留原称谓

将“4#楼东侧”“4栋东立面”等原始称谓映射到同一项目部位编号时，保留每处原文及来源。编号至少能表达项目、楼栋/单体、楼层或范围、区域/朝向、细部；未知层级留空。项目范围、精确部位、多楼栋同框、拍摄位置、画面中的施工对象是不同概念。跨时间工序比较必须能证明指向同一对象；仅同项目或同批次不够。轴线定位必须有图纸轴号和照片可辨的构件/相机方位支撑。

### 2. 图纸版本随定位一起记录

每次图纸定位记录文件路径、文件哈希、图号、图名、版本/出图日期、页或布局，以及定位依据；不明版本标记未知。存在设计变更时保留旧版与新版的适用时间和差异，不用新版图纸静默解释旧照片。只有总平图时可定位楼栋相对关系，不能因此推定楼层和轴线。

### 3. 进度语义分层

区分 `计划/安排`、`据文字报告已施工`、`照片可见施工中`、`照片可见形态完成`、`有验收记录证明验收完成`。日报里的“今日完成”、会议纪要里的“要求完成”、照片里的“外观已成形”不能互相替代。对一个工序记录动作、对象、部位、发生日期或区间、信息来源和状态；无法证明的完成率留空。照片未拍到某工序不能推定未施工；围护消失等项目经验规则须保持适用条件及独立不确定性。

### 4. 来源、置信与修正历史

每条推断或确认记录来源类型、原文件或照片 ID、证据位置、提取/确认时间、确认主体和状态（模型候选、用户确认、冲突待核等）。回答中能够回到原照片、文档页码/段落或图纸图号。修改保留旧值、新值、修改原因与时间；同一用户提供的锚点不自动使其衍生匹配变成用户确认。已入库与仅在本轮对话临时使用的信息必须明确区分。

### 5. 资料覆盖与缺口

记录照片/文档覆盖的时间、楼栋、部位和视角，以及遮挡、远景、仅局部等限制。查询时说明哪些结论由证据覆盖，哪些时间段或部位没有资料。`没有发现证据` 不等于 `没有施工`。时间线允许跳段，不填造中间工序；必要时说明同一位置的前后照片不足以确定具体转序日。

## 四、查询时的组织方式

先按项目、时间范围、部位编号检索，再按证据状态过滤或标注；同时核对相关文档和图纸版本。答复优先给“日期/区间—部位—工序状态—依据”，每个关键结论附原照片或资料定位。注明日期和部位是用户确认、文档记载还是模型候选，明确计划与实际、形态完成与验收完成的差别。回答“此前做过什么”可列证据时间线；回答“进度多少”只有计划量、实际量及口径齐全才计算百分比。

## 五、扩展现有实现时的验收点

若用户要求将上述能力实际长期入库，扩展时至少支持：批次及成员例外；文档原件与可定位片段；带版本的图纸依据；统一部位及别名；分层工序事件；证据之间的关系；字段级来源和审计；资料覆盖范围。导入必须可重复执行且不复制同一原件；旧库迁移不丢现有照片、确认和审计记录。查询同时返回结果与原始证据路径，未实现的字段不伪装成已确认或已保存。
